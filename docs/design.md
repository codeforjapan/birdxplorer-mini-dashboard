## 1. デザインの方向性

**コンセプト: 観測装置のコンソール。**

このサイトは論説ではなく計器である。地震という一点の出来事を起点に、そこから何時間後にどんな誤情報が湧いたかを読み取る道具として設計する。したがって、

- **明るい面**を基調とする。「暗い面でしか多色が判別できない」という前提は当初の設計判断だったが、これは検証されないままの思い込みだった。実際には、8色に絞り・白背景上での隣接色対比較(protan/deutan/tritan の色覚多様性シミュレーションと通常視の双方)を個別に検証したことで、白背景の上でも8色は安全に判別できる。判別性は面の明暗ではなく、色数を絞ったうえでの検証によって担保している(§2.1・§3)
- **時刻と数値はすべて等幅**。計器の目盛りとして読むものであり、プロポーショナルフォントでは桁が揃わず比較できない
- **散文はサンセリフ**。レポート部分だけは読み物なので、計器の書体から切り替える
- **本震の瞬間を示す赤い縦線**が全体のアンカー。すべての情報はこの線からの相対時間として読まれる。この1本以外に赤は使わない

装飾は置かない。余白と整列だけで構造を示す。

## 3. クラスタパレット

クラスタはLLMが動的に生成するため、色は名前ではなく `colorIndex`（0-7）に紐づける。`colorIndex` はクラスタ生成時に採番し、以後変更しない。IDが永続なので色も永続する。

**8色が上限。** カテゴリ色を無限に増やせない、あるいは循環させて重複させられないのは、データビジュアライゼーションの色覚多様性(CVD: 色覚多様性シミュレーション上の識別可能性)の観点から、白背景の上で隣接する色同士を安全に見分けられる categorical hue の数に上限があるため。この8色はセットとして検証済みで、隣接ペアの最悪値は protan(1型2色覚)シミュレーションで ΔE 9.1、通常視で ΔE 19.6 を確保している。**この並び順(index)自体が色覚多様性対応の担保であり、装飾上の都合で並べ替えてはならない。**

| index | hue | 値 | 対白コントラスト |
|---|---|---|---|
| 0 | blue | `#2A78D6` | — |
| 1 | orange | `#EB6834` | — |
| 2 | aqua | `#1BAF7A` | 2.82:1 (要relief、下記) |
| 3 | yellow | `#EDA100` | 2.17:1 (要relief、下記) |
| 4 | magenta | `#E87BA4` | 2.69:1 (要relief、下記) |
| 5 | green | `#008300` | — |
| 6 | violet | `#4A3AA7` | — |
| 7 | red | `#E34948` | — |

「その他」(9位以下の集約色。`OTHER_CLUSTER_COLOR`): `#94A3B8`

**検証時のWARN(却下不可)**: aqua・yellow・magenta の3色は白背景に対して3:1を下回る。これは色を面積の大きいグラフセグメントとして使う分には許容するが、**色を情報の唯一の担い手にしてはならない**という要件が必須の緩和策(relief)になる。凡例チップとバッジには必ずクラスタ名をテキストで併記し(§6.4・§6.5)、グラフには表形式のフォールバックを必ず用意する(§10)。この2点が崩れると WARN を無視したことになるため、実装変更時も必ず両方を維持すること。

**9個目以降のクラスタが生まれた場合**: 件数上位8クラスタに 0-7 を割り当て、9位以下は「その他」として `#94A3B8` に集約する。グラフ上は1本のセグメントにまとめ、詳細パネルでは内訳を個別に表示する。

**旧10色パレットからの移行について**: 以前は10色パレットだった。パレットを8色に絞った後も、旧パレット時代に採番済みの `colorIndex` が 8 や 9 の永続データは残り得るが、`clusterColor()` が `colorIndex % パレット長` で色を引くため、8→blue・9→orangeのように既存の8色のいずれかに再マップされ、表示が壊れることはない(色が別の実クラスタと重複することはあるが、名前は必ず併記されるため識別自体は失われない)。

**色の使い方**:
- グラフのセグメント: 不透明度 90%
- 凡例で他カテゴリが選択されている時の減光: 不透明度 35%
- バッジ背景: 同色の 13%（16進で `22` サフィックス）。**文字色は本文インク `#374151` 固定**、クラスタの色identityはバッジ先頭の6px丸ドットで担う

**既知の懸念(解決済み)**: 白いカード背景に移行した際、上記2箇所は暗い面を前提にした値をそのまま持ち越していたため、実測すると次の問題があった。

1. 凡例減光(旧12%): どのクラスタ色でブレンドしても対白コントラストが概ね1.1〜1.2:1程度まで落ち、非選択セグメントが実質見えなくなり、フィルタ中はグラフ全体が「読める形」でなくなっていた。
2. バッジ(同色13%の背景に同色の文字): 8色中6色で対白コントラストが4.5:1を下回っていた(実測: blue 3.75 / orange 2.77 / aqua 2.47 / yellow 1.96 / magenta 2.39 / red 3.34 / その他 2.31。green 4.12 と violet 6.91 のみ通過)。

いずれも§10の「本文4.5:1以上」「色を情報の唯一の担い手にしない」という原則そのものに反していたため、次のように是正した。

- 凡例減光は **35%** に引き上げた。選択中(90%)との差ははっきり残したまま、非選択セグメントも見える状態を保つ(要求されるのは本文同等の4.5:1ではなく「消えない」ことなので、この値で足りる)。
- バッジは**文字色を本文インク`#374151`固定**にし、代わりに**6pxの丸ドット**をバッジ先頭に置いてクラスタの色identityを運ぶ形に変えた。文字の可読性(色に依らず一律で高コントラスト)と色による識別(ドットという専用の形に切り出す)を分離した結果、8色すべてで対白コントラストが8.2:1以上になった(実測: blue 8.72 / orange 8.90 / aqua 9.01 / yellow 9.29 / magenta 9.10 / green 8.52 / violet 8.29 / red 8.68 / その他 9.27)。

### 6.6 クラスタ別Note一覧

詳細パネル(§6.5)が「選択中の時間帯」を軸にノートを並べるのに対し、こちらは**クラスタ**を軸にした相補的なビュー。詳細パネルの直下、独立したカードとして配置する(レポートセクションの手前)。凡例チップの既存のクリック挙動(強調/減光。§6.4・§7)とは別のツールであり、変更しない。

- クラスタ行は**件数降順**でソートする
- 各行(折りたたみ状態): クラスタ色スウォッチ＋クラスタ名＋件数。クリックで展開し、そのクラスタのノートを新しい順に一覧表示する。再クリックで折りたたむ
- **複数クラスタを同時に開ける**(比較が目的のため)。`<details>`要素に`name`属性を付けない実装により、ネイティブの排他制御(1つしか開けない挙動)を避ける
- 各ノート項目は次の3点のみを表示する:
  1. 作成日時: `MM/DD HH:MM`・等幅11px・ラベルインク。クラスタは複数日にまたがるため、詳細パネル(§6.5、ビン見出しが日付を兼ねる)と異なりここでは日付が必須
  2. ノート本文(`summary`): 13px・本文インク・行間1.7
  3. 「Xで見る」リンク: 11px・新規タブ・`rel="noopener noreferrer"`
- クラスタバッジは項目に付けない(クラスタ単位でグルーピングされているため冗長)
- **9位以下でグラフ・凡例が「その他」に集約するクラスタも、ここでは個別の行として表示する**(§3)。ノートが持つ吸収済み(alias)のクラスタIDは`resolveClusterId`で解決してから現存クラスタに紐づける
- `?showExcluded=1`時は他の箇所と同様、除外ノートも表示対象に含める。Stage1(関連性判定)で閾値未満と判定されたノートは`clusterId: null`のまま確定し(Stage2に進まない)、実質的にほぼすべての除外ノートがどのクラスタにも属さない状態になる。これをそのまま捨てると`?showExcluded=1`で除外ノートを開いても件数が増えず、このフラグの目的(管理ビューでの閾値チューニング検証)を果たせないため、`clusterId`が null のノートは詳細パネル(§6.5)と同じ「未分類」という1行にまとめて必ず表示する
- キーボード操作: 行はEnter/Spaceで開閉でき、`aria-expanded`相当の状態と展開領域の関連付けが取れること。`<details>`/`<summary>`はこれらをネイティブに提供するため、手書きのARIAより優先して使う(§10)
- 空状態: あるクラスタに可視ノートが1件もない場合は「このクラスタに該当するNoteはありません。」と表示する
- 開閉のトランジションは色・不透明度の変化(§7)に限定し、高さのアニメーションやスライドインは行わない(「計器なので動かさない」)

**管理ビュー（`?showExcluded=1`）時の表示**: 「未分類」への集約だけでは、そのノートが除外されたものだと一目で分からない。そのため除外ノートの項目には、タイムスタンプの隣に「除外」ラベル(等幅10px・`bg-block`背景・本文（弱）インク`#4B5563`)を明示し、さらに項目の下にスコア・除外理由の行(等幅11px・`#4B5563`)を追加する。spec.md §4 Stage1「一覧・スコア・理由を確認でき、閾値のチューニング検証に使う」を満たすための表示。既定ビューでは`relevance`・`excludeReason`はサーバーから送らず(値をpropsに一切乗せない)、内部スコアを公開サイトに晒さない。

### 6.7 レポートセクション

水平罫線で区切った下に配置。

- アイブロウ「REPORT」: 等幅11px・大文字・`#8892A0`
- h2: レポートタイトル
- メタ行: 生成時刻・データソース・**「このレポートはAIが自動生成しており、人手による検証を経ていません」**。11-12px・等幅・`#8892A0`。この一文は常時表示し、折りたたまない
- 本文: Markdown をレンダリング。13px・`#374151`・行間1.7

**クラスタ別ブロック**: 各クラスタの解説は独立したブロックとして描画する。
- 背景 `#F8FAFC`、**左端に4pxのクラスタ色の縦帯**、角丸8px、パディング 16px×14px
- ブロック内の見出し行: 連番（10px・等幅・`#8892A0`）＋ クラスタ名（14px・Semibold・見出しインク `#0F1419`）＋ 件数バッジ
- 説明文: 13px・`#4B5563`

**ブロック判定は見出しの構造で行い、クラスタ名の文字列一致には依存させない。**

ダイジェストの Markdown は自由な散文ではなく、生成側・描画側で共有する構造契約(`src/lib/llm/contract.ts` の `DIGEST_SUMMARY_HEADING` 付近、生成プロンプトは `src/lib/llm/report.ts`)を持つ:「`## クラスタ別まとめ`」見出しの直下に「`### {連番}. {クラスタ名}（{件数}件）`」が1クラスタ1見出しで並ぶ。**「`## クラスタ別まとめ` の直下にある `###` はすべて無条件にクラスタ別ブロックとして描画する」**——これが判定の唯一の基準であり、見出し文字列が現在のクラスタ名に解決できるかどうかは一切関与しない。

これは以下の運用実態への対応である:
- **レポートはある時点のスナップショット。** 累積レポート・日次ダイジェストはいずれも生成時点のクラスタ名・件数を Markdown に書き出したもので、その後 Stage 3(recluster)によってクラスタが**改名**されたり**マージ**されたりしても、書き出し済みの Markdown 本文は書き換わらない(日次ダイジェストは確定後イミュータブル。spec.md §5.2)。
- **したがって見出し文字列は将来ズレることが前提。** 改名・マージ後は現在のクラスタ一覧のどれとも一致しなくなりうる。ここで「一致しないなら普通の見出し+段落に格下げする」という実装は、クラスタ数が多い日ほど・運用が長引くほど広い範囲を巻き込んで壊れる。ブロックとして描画するかどうかを名前解決の成否に委ねてはならない。

名前解決の成否が左右してよいのは**色と件数バッジという装飾だけ**である:
- **解決できた場合**: そのクラスタの `colorIndex` に対応する色を左帯に使い、**現在の**件数(生成時点の件数ではない)を件数バッジに表示する。レポート本文中の件数(生成時点のスナップショット)とバッジの件数(現在値)が食い違って見えることがあるが、これは snapshot vs 現在値という性質上避けられない差であり、バグではない。
- **解決できない場合(改名・マージ後)**: 左帯は「その他」集約と同じ中立色 `#94A3B8`(`OTHER_CLUSTER_COLOR`)にし、**件数バッジは表示しない**(誤った数字を出すくらいなら出さない方がよい)。ブロックとしての背景・角丸・パディング・連番は解決可否に関わらず同一。

名前解決は「先頭の連番・末尾の`（N件）`・全角/半角括弧の差」だけを吸収する軽い正規化で行い、**単語の並べ替えや同義語には対応しない**(例:「HAARP・人工地震による地震誘発説」→「人工地震・HAARPによる誘発説」のような改名は解決を諦め、中立色にフォールバックする。これが正しい動作であり、より賢い文字列マッチングで追いかけるべき対象ではない)。

**渡すクラスタ一覧は集約前の全件。** グラフ・凡例で使う上位8+「その他」集約(§3、`buildDisplayClusters().order`)は9位以下を丸ごと畳んでしまい、レポートの名前解決には使えない(9位以下のクラスタの説明が絶対に色付きブロックにならなくなる)。レポートセクションには集約前の全アクティブクラスタとその時点の件数(`src/lib/view.ts` の `buildAllDisplayClusters`)を渡す。

**まとめブロック**: 枠線 `#E2E5EA` のカード。箇条書き、各項目の冒頭語のみ `#0F1419`。判定は見出しの**先頭一致**(`/^(まとめ|総括)/`)で行う。部分一致にすると「クラスタ別まとめ」まで拾ってしまうため。「クラスタ別まとめ」自体は契約上見出しのみで本文を持たない区切りであり、本文が空の見出しは(まとめブロックか否かに関わらず)空カードとして描画しない。

**日次アーカイブ**: レポート末尾に日付リンクの一覧を置き、`/report/YYYY-MM-DD` へ遷移させる。

## 10. アクセシビリティ

- 本文テキストと背景のコントラスト比 4.5:1 以上を確保する(§2.2に実測値を記載)。`#9AA3AF`(注釈)・`#8892A0`(ラベル・軸目盛り、3.15:1)は本文には使わない
- 色は情報の唯一の担い手にしない。凡例チップとバッジには必ずクラスタ名を併記する。これは §3 で aqua・yellow・magenta が対白3:1を下回ると分かった上での必須の緩和策(relief)であり、削除・弱体化しないこと
- グラフのバーと凡例チップはキーボードで到達・操作可能にする。フォーカスリングは `#0F1419`(見出しインク)の2pxアウトライン、2pxオフセット。旧仕様の `#E8EAED` は白背景では不可視になるため見出しインクに変更した
- 明滅ドットとすべてのトランジションは `prefers-reduced-motion: reduce` で無効化する
- グラフには代替として、詳細パネルと同等の内容を読める表形式のフォールバックを用意する

## 11. やらないこと

- グラデーション、ドロップシャドウ、グラスモーフィズム
- アイコンの多用（「Xで見る」以外にアイコンを置かない）
- クラスタ色以外の彩度の高い色
- 数値のカウントアップアニメーション、要素のスライドイン
- ライトテーマとダークテーマの切り替え。このサイトは**ライトオンリー**であり、ダークテーマは提供しない。以前は逆に「暗い面が前提でライトテーマは用意しない」としていたが、白背景上で8色の判別性を検証できたため面を明るい側に一本化した(§1)。トグルを追加しない(ダークテーマ自体が存在しない)という結論は変わらない
